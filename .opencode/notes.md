## Decisions
- Use `glsl_parse_string` only (avoids FILE*/stdio)
- Pointers passed as i32 across WASM boundary
- `-DNDEBUG` to eliminate assert dependency
- fprintf/exit/fread/etc. stubbed (dead code paths in our usage)
- Free-list allocator with coalescing on top of WASM memory.grow()
- `--import-memory` — JS controls memory, provides initial pages
- `__heap_base` exported by wasm-ld marks heap start after data segment

## Discoveries
- `clang --target=wasm32-freestanding` works on this system (clang 18.1.8)
- `__builtin_offsetof`, `__builtin_va_list` all available in freestanding mode
- flex-generated code uses `FILE*` as a type but `glsl_parse_string` never calls FILE functions
- glsl-parser uses a bump-pointer arena allocator (1MB buffers) - only needs malloc for arena chunks
- `strdup` in lexer is called for every identifier token (original not freed after arena copy — minor leak)
- Compiler auto-generates `memcpy` calls for struct/array copies at -O2 — needed to provide it
- flex-generated code needs: stdin, stdout, fwrite, fread, getc, ferror, clearerr, errno, EINTR, EINVAL, ENOMEM, isatty, fileno — all stubbed

## Gotchas Fixed
1. Allocator started at memory base 0, colliding with data segment → fixed by using `__heap_base`
2. `__grow_memory` needed to return memory size, not base address → fixed interface
3. `memcpy` was auto-generated by compiler → added implementation
4. `vsnprintf` needed for `glsl_ast_generate_glsl` → implemented minimal version (%s, %d, %u, %f, %c)
5. WASM module needed `--import-memory` with proper initial page count → set to 2 pages
